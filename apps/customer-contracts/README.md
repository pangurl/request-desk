# 客户与合同管理系统

面向提供订阅式软件与企业服务的中小团队，管理客户档案、服务合同及内部审核。采用若依常见的后台信息结构：侧栏导航、业务概览、查询列表、详情抽屉、角色权限与操作记录；业务代码独立实现，不包含若依 Java 后端。

## 项目背景

软件服务团队在获客和续签过程中，通常需要在客户表格、合同文件与聊天记录之间核对信息。本项目把客户维护、合同起草、内部审核及台账查询放入同一工作空间，重点解决三类问题：

1. 客户与合同分散：合同关联客户档案，详情可回到客户的合同列表，减少重复查找。
2. 流转边界不清：草稿、待审核、退回、生效分别限定操作，退回必须说明原因，生效后禁止修改草稿。
3. 多人协作覆盖：请求携带版本号，服务端事务校验；冲突提示核对，前端保留未提交内容，不用旧输入静默覆盖新数据。

这是可运行的个人开发项目，初始化数据均标注为示例。未声称有实际企业客户、生产流量或商业交付业绩。

## 角色与业务流程

| 角色 | 查看数据 | 客户维护与草稿编辑 | 提交审核 | 通过与退回 | 操作记录 |
| --- | --- | --- | --- | --- | --- |
| 管理员 | 本租户 | 支持 | 支持 | 支持 | 支持 |
| 业务员 | 本租户 | 支持 | 支持 | 禁止 | 禁止 |
| 只读成员 | 本租户 | 禁止 | 禁止 | 禁止 | 禁止 |

1. **客户建档**：录入名称、联系人、邮箱、行业和状态；同名客户可以存在，实际企业应按统一社会信用代码进一步去重。
2. **创建合同**：从本租户启用客户中选择，自动展示联系人；填写名称、金额与起止日期，保存草稿。
3. **提交审核**：业务员核对草稿并提交；待审合同不能继续编辑。
4. **审核处理**：管理员通过后合同生效；退回时填写原因，业务员修改后重新提交。
5. **查询追溯**：按客户、标题和状态筛选，服务端分页；查看流转时间线、按筛选导出 CSV 台账。
6. **状态一致性**：审核成功先更新当前详情，再重新查询当前列表与完整详情；在待审筛选下，记录不再属于队列，会从列表消失。
7. **失败处理**：网络或校验失败不关闭输入窗口；409 冲突保留表单或处理意见，明确载入服务器版本后再决定如何处理。草稿载入前提示用户复制未保存内容，不自动合并业务字段。

## 功能需求与实现范围

| 模块 | 已实现需求 | 关键约束 |
| --- | --- | --- |
| 登录与会话 | 账号登录、退出、会话过期校验、连续失败限制 | 服务端保存会话摘要；密码加盐 scrypt；HttpOnly、SameSite Cookie |
| 多租户 | 用户归属租户，客户、合同、操作记录按租户查询 | 客户关联写入同时校验租户，越权详情返回 404 |
| 客户档案 | 新增、编辑、启停、搜索、分页、详情、关联合同入口 | 停用后保留历史，不允许创建或提交新合同 |
| 合同台账 | 草稿录入、客户联动、金额与日期校验、筛选分页、导出 | 金额以整数分存储；结束日期不早于开始日期 |
| 审核流转 | 提交、通过、退回、修改、重提 | 固定流程，管理员审核；版本校验与操作日志在同一事务中 |
| 操作留痕 | 客户修改、合同修改与流转、导出记录 | 管理员查看本租户日志，不提供页面删除入口 |
| 业务概览 | 客户总数、待审数、生效数、生效金额、状态图表 | 数据来自 API；金额合计不是实收金额 |
| 交互与异常 | 加载态、空列表、失败提示、禁用越权按钮、冲突恢复 | 后端再次校验权限，前端按钮不构成安全边界 |
| 工程交付 | TypeScript 检查、按路由分包、组件按需引入、测试、容器配置 | 不依赖在线 Mock 服务；前后端可同源运行 |

未实现电子签章、合同附件、回款/开票、可配置多级工作流、在线支付、客户自助开租户与账号管理页面。本系统“生效”指内部审核完成，不代表取得电子签名或法律上的合同效力。当前是服务团队内部的租户工作空间，不是完整商业 SaaS 平台。

## 技术栈与具体用途

| 层次 | 技术 | 实际用途 |
| --- | --- | --- |
| 页面基础 | HTML、CSS、JavaScript、TypeScript | 响应式布局、表单逻辑、接口类型与编译检查 |
| 组件开发 | Vue 3 Composition API、Vue Router | 页面与抽屉组件、路由守卫、动态导入 |
| 全局状态 | Pinia | 登录用户、租户角色、写入权限；表单状态留在业务页面 |
| UI | Element Plus、官方图标、中文语言包 | 列表、分页、日期、表单、弹窗、时间线；按需引入 |
| 网络 | Axios、HTTP、REST、JSON | 同源会话、超时、业务错误反馈、CSV 下载 |
| 图表 | ECharts 按模块引入 | 合同状态柱状图，ResizeObserver 适配尺寸，卸载销毁实例 |
| 服务端 | Node.js 24、Express 5 | REST API、会话鉴权、权限检查、参数校验、静态页面托管 |
| 持久化 | SQLite、SQL、Node 内置 node:sqlite | 真实磁盘数据库、外键、租户索引、事务与版本锁 |
| 安全基础 | node:crypto、Cookie | scrypt 密码摘要、随机会话与摘要存储、登录失败限制、请求来源检查 |
| 构建与部署 | Vite、npm lockfile、Docker | 开发代理、生产分包、锁定依赖、多阶段镜像、数据卷 |
| 质量验证 | node:test、assert、浏览器自动化 | 流程、越权、租户隔离、并发、持久化及交互验证 |

没有为了数量加入 React、Zustand、Java、MySQL 或 Redis。它们不是本版本的已用技术。SQLite 适用于当前单实例范围；多实例部署需先迁移数据库与会话机制。

## 运行

需要 Node.js **24+**。本目录独立安装，不使用仓库其他应用的依赖。

```bash
npm ci
# 终端一：API 与本地数据库，端口 3100
npm run server
# 终端二：Vite 页面，使用终端输出的地址，通常是 http://localhost:5173
npm run dev
```

首次启动创建账号：`admin`（管理员）、`sales`（业务员）、`viewer`（只读）、`tenant2`（另一租户管理员）。开发环境默认初始密码 `LocalDemo2026!`，用于本地验证。可在第一次启动时通过 `INITIAL_PASSWORD` 指定自己的密码；已有数据库的密码不会被环境变量重置。不同租户账号查询结果应完全隔离。

```bash
npm test
npm run build
# 生产模式同源托管页面与 API；首次初始化使用自己的密码，至少 12 字符
INITIAL_PASSWORD='请替换为你自己的长密码' HOST=0.0.0.0 npm start
```

Windows PowerShell 对应设置方式：

```powershell
$env:INITIAL_PASSWORD='请替换为你自己的长密码'
$env:HOST='0.0.0.0'
npm start
```

打开服务器的 `3100` 端口。数据默认保存在 `data/contracts.sqlite`，重启保留。可通过 `DATABASE_PATH`、`PORT`、`HOST` 配置。

### 容器部署

```bash
# 首次运行必须传入你设置的密码；不要把真实密码提交到 Git
INITIAL_PASSWORD='请替换为你自己的长密码' docker compose up -d --build
```

映射 `3100` 端口，命名卷保留数据库。公网部署应配置域名、HTTPS 反向代理与备份；仅在受控反向代理后运行时设置 `TRUST_PROXY=1`，由代理覆盖 `X-Forwarded-Proto`，以便 HTTPS 会话启用 Secure Cookie。本仓库未替你购买或开通云服务器。GitHub 保存源码，**GitHub Pages 无法运行本项目 Node API 与 SQLite**，不能把静态页面链接视为完整业务服务。

## API 索引

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/login`、`/api/logout` | 登录、退出 |
| GET | `/api/me` | 会话角色与租户 |
| GET / POST | `/api/customers` | 客户分页查询、新建 |
| GET / PUT | `/api/customers/:id` | 客户详情、版本校验更新 |
| GET | `/api/customer-options` | 当前租户启用客户选项 |
| GET / POST | `/api/contracts` | 合同分页查询、草稿创建 |
| GET / PUT | `/api/contracts/:id` | 合同详情、草稿修订 |
| POST | `/api/contracts/:id/actions` | `submit / approve / return`，必须携带 `version` |
| GET | `/api/contracts/export` | 按相同筛选导出，最多一万条，规避 CSV 公式注入 |
| GET | `/api/events` | 管理员查询操作记录 |
| GET | `/api/dashboard` | 本租户业务统计 |

成功返回业务 JSON；错误返回 `{ "error": "原因" }`，使用 401 / 403 / 404 / 409 / 422 / 429 状态码。当前筛选查询以 `page`、`size`、`q`、`status`、`customer_id` 传参；日期 `YYYY-MM-DD`，金额 `amount_cents` 为整数。

## 验证内容

`npm test` 使用独立临时 SQLite 文件和真实 HTTP 请求，验证 10 个业务场景：登录、跨站请求拦截、角色权限、客户乐观锁、租户隔离、金额日期校验、退回重提、并发审核、导出统计与停用限制、重启持久化及退出。详细条目见 `server/app.test.mjs`。

浏览器检查脚本位于 `scripts/browser-check.mjs`，Playwright 是开发依赖，首次使用安装 Chromium 后运行：

```bash
npx playwright install chromium
npm run build
npm run test:browser
```

可用 `CHROMIUM_PATH` 指定已有 Chromium 可执行文件，或用 `PLAYWRIGHT_MODULE_PATH` 指定外部 Playwright 安装。它验证新增客户与合同、审核后的待审队列、冲突输入保留、窄屏以及 JavaScript 错误，不作为浏览器依赖加入生产应用。
